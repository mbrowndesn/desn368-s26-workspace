A reflection on the design and development process behind Base Camp — a responsive field guide built for DESN368.

Design Decisions

What design choices did you make and why?

The color palette — dark olive green, warm amber, and tan — was chosen to evoke the natural, grounded feeling of being outdoors. I wanted every design choice to feel like it belonged in the wilderness: earthy, deliberate, and unhurried. Bright or saturated colors would have felt wrong for a camping guide; these tones feel lived-in and honest.

The font pairing was equally intentional. Sigmar One for the display title brings a bold, rugged character that reads as adventurous without being loud. Patrick Hand was chosen for body text because its handwritten quality gives the guide the feeling of actual field notes — something a seasoned camper might have scrawled in a journal. Together they balance authority with warmth.

Alternating section backgrounds between amber and dark green create a clear visual rhythm that helps readers track their position in the guide. This pattern also solves a practical problem: long single-page sites can feel monotonous. The alternation breaks the content into digestible chapters with distinct visual identities.

Technical Challenges

What was difficult to code? How did you solve it?

The most challenging piece was the CSS-only hamburger menu. Using a hidden checkbox input paired with a label and a sibling CSS selector to toggle the sidebar on mobile was an entirely new pattern. Getting the specificity right — and ensuring the sidebar animated in and out — took significant trial and error. The breakthrough was understanding that CSS can only select forward siblings, which shaped how I had to structure the HTML.

The fixed sidebar offset was another stumbling block. Because the sidebar uses position: fixed, it is removed from the document's normal flow — meaning the header and main content have no awareness it exists. To prevent content from sliding behind it, both the header and main needed an explicit margin-left equal to the sidebar's width. Understanding this pattern was a key moment in how I think about CSS positioning.

Responsive Strategy

How did you adapt your design for mobile?

The central responsive challenge was the sidebar. A fixed sidebar works beautifully on desktop but consumes too much screen space on mobile. My solution was to slide it off-screen by default and animate it back into view when the hamburger is checked. This preserves the sidebar's visual identity while keeping it out of the way until needed.

At the 900px breakpoint, all section layouts switch from flex-direction: row to flex-direction: column. Section photos that sit beside text on desktop stack below their paragraphs on mobile and expand to full width. The margin-left offset on the header and main is removed entirely so content fills the screen edge to edge.

Typography scales through a three-step system: the base html font-size drops at 600px and rises above 1200px. Because all type sizes are set in em units, this single change cascades consistently across every text element without requiring dozens of individual media query overrides.

Learning Moments

What did you learn about Flexbox or CSS positioning?

Flexbox was the single biggest conceptual leap in this project. Early on I kept trying to style flex items directly to achieve layout effects that only work on the flex container. Understanding that properties like justify-content and align-items live on the parent — and that flex children are controlled by that parent — completely changed how I approach layout problems.

The position: relative and position: absolute relationship was equally clarifying. Before this project I used absolute positioning mostly by accident. Building the hero section's floating mountain image taught me that absolutely positioned elements escape normal flow and anchor to the nearest positioned ancestor. Once I understood that rule, the whole system felt logical rather than arbitrary.

Future Improvements

What would you add or change with more time?

The most meaningful improvement would be scroll-triggered animations. Right now the page loads statically — sections simply exist. With more time I would explore ways to have each section fade in as the user scrolls to it, making the experience feel more like turning pages in a real field guide. The content deserves that kind of pacing.

The mobile hamburger menu currently stays open when a user taps a navigation link, requiring a second tap to close it. This is a small friction point I would fix. I would also revisit the hero section on smaller screens — the floating mountain image loses its impact when stacked linearly, and a different approach would serve mobile better.

Finally, I would organize the CSS more carefully. Managing three brand colors across dozens of selectors was tedious and easy to get wrong. A more structured approach to the stylesheet would make future changes much easier and bring the code closer to what is used in professional development.
